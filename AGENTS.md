# Project TinyWorld — Agent Context

Consolidated from design threads (Gemini brainstorm "Project Quantum" Mar 2026 + Zo build sessions Jun 2026). This file is the source of truth for project state. Update it as the project evolves.

## What this is

Persistent, cloud-based AR world sim for iPhone. LiDAR-scan a physical space → it becomes a Minecraft-like voxel "tiny world" (12×12 blocks/sq ft) populated by semi-autonomous AI "Tiny People," under threat from "The Void." Worlds are geo-anchored; connecting two worlds requires physically scanning the path between them ("bridging"). Formerly called **Project Quantum**.

## Key design decisions (settled)

1. **Worlds are data, not processes.** No per-world VMs. Worlds = rows in SQLite (`data/tinyworld.db`), simulated lazily on access (catch-up sim: elapsed time × void rate × weather). Ports to Postgres/Supabase later. See `docs/persistence-and-access.md`.
2. **Geography is the auth layer.** Access via geo gate (GPS within 150 m of anchor) OR a live bridge (integrity > 0). Bridges decay ~8 pts/day unless re-scanned; anchor structures (cairn → lidar_tower) slow decay. No accounts in prototype. **REAFFIRMED Jun 27: the owner is NEVER exempt — no owner-bypass, no `?owner=` shortcut, nothing that hides the gate behind account ownership.** A wrong owner-bypass was added to `/api/tinyworld-worlds` and the staging frontend and immediately reverted; do not reintroduce it. The only testing affordance is the node override `?nodeLat=&nodeLon=` (forces a GPS-tier node at a REAL anchor coord — the gate still evaluates normally). Gotcha: a coarse/foreign egress IP (observed resolving to London on Jun 27) hides all NYC-anchored worlds even for the owner — that is the gate working, not a bug. Fix is GPS-in-range or the node override, never an owner exemption.
3. **Voxel pipeline core = OpenMVS/GLB finalizer only.** The canonical saved-world path is phone video capture -> COLMAP/OpenMVS mesh -> gravity-aligned GLB -> TinyWorld GLB voxelizer. Use `tools/old_path_from_capture.py` as the project-owned entrypoint and `tools/glb_to_world_payload.py` as the GLB-to-world payload converter. The old Depth-Anything/RGB-D/TSDF path has been removed from the active project and must not be used as fallback/preview/debug. Keep `dda-voxelize` concepts only as legacy/reference naming if useful. The user-facing path remains camera capture inside `/tinyworld`, but its final world must be the OpenMVS/GLB payload. Phased/progressive reveal may exist as UX later, but not via Depth/TSDF and not as a saved-world builder.
4. **Semantics from GPS, geometry from LiDAR.** LiDAR gives shape only; GPS unlocks the semantic layer (OSM landuse + ESA WorldCover + Köppen climate + Open-Meteo weather + date/season) → block palette. v1 accepts raw geometry + biome palette (no surface classifier).
5. **Void follows real time.** Night (8pm–6am local) = aggressive; winter = +25%. Biome sets hostility + creature archetypes. NYC: Soot Crawlers (roads), Girder Shades (walls), Steam Wraiths (waterfront), Concrete Nulls (rare). See `docs/biome-nyc-temperate.md`.
6. **Turn-based action/pause cycle** to absorb cloud latency. User builds = blueprint; Tiny People execute it (delayed). Combat turn-based.
7. **Tiny People (Ghibli Aesthetic)**: commandable, not controllable. Moving away from voxel geometry toward **pixelated Studio Ghibli-style sprites** (billboarded in the 3D world). MBTI-style archetypes; happiness/longevity/independence metrics; voice commands; they talk back as the UI. Pocket dimension: carry them on-device, deploy in new scans; abandoned ones navigate home. See `docs/tiny-people.md`.
8. **The Supplier (The Sentinel)**: A massive 10-15 block tall entity. It "wakes up" when the user is controlling the world and sits back down to become a static part of the landscape when the user leaves. Acts as the world's protector and source of raw materials. See `docs/sentinel-supplier.md`.
9. **Scan composition via tectonics (Jun 13).** Scans compose into a single geo-anchored world, not isolated islands. Geo-tag is the canonical anchor; one scan per region (3 exceptional re-scan cases); seams between adjacent scans are where tectonic events happen and where builds are at risk; interior is permanent. Manual coarse + ICP fine alignment on submission. Displaced mass flows to the Void pool, ledger conserved. See `docs/scan-composition-and-tectonics.md`. **Conflicts with #2's "each scan = own world" model — bridges remain as access control but the underlying geometry unifies; schema migration deferred until implementation starts.**
10. **World simulates lightly while the player is away (Jun 23).** When the Sentinel sleeps / the player leaves, the world remains alive: villagers continue to act, small builds can progress, and the Void creeps slowly. Returning should feel like time passed and the survivors had inner life, but the offline sim must be bounded and legible: no huge irreversible surprises without recap, warning, or player agency.
11. **Stockpile must be visible, not an invisible inventory (Jun 23).** "What blocks you see is what you get." The ledger pool can still be named STOCKPILE internally, but it must represent physical piles, carried blocks, crates, carts, or villager-held materials in the world. There is no gifted/free building, including onboarding. Every player or worker build must consume visible existing blocks from the world, a carried block, or a visible local stockpile. If the player cannot see or locate the material, it cannot be spent.

- **Conservation ledger (Jun 11; stockpile clarified Jun 23)**: One law for everything: `WORLD + STOCKPILE + BUILT + VOID === baseline`, always. Blocks move between pools, never created/destroyed. **VOID doubles as the world's reservoir** — organic growth draws from it (`spawnBlockInto` auto-logs VOID→WORLD), decay/removal returns to it; this rule is load-bearing, without it the organic lifecycle breaks the invariant within seconds. Fresh scans seed VOID with 2% of scan mass so growth has matter to draw from. Carried blocks (player or worker) live in STOCKPILE; failed worker placements keep the block in hand instead of vanishing. **Important design constraint:** STOCKPILE is not a hidden inventory. It must map to visible matter in-world: carried blocks, physical piles, carts/crates, or villager-held materials. All construction, including worker construction and onboarding, must physically take from existing visible blocks. Building should spend nearby visible material; if the player cannot see or locate the block, they should not be able to spend it. Every move queues a `block_events` row (kind grow/remove/cycle), aggregated client-side and flushed every 15s / on save / on pagehide (sendBeacon). Pools persist in save `meta.ledger`; WORLD is recounted authoritatively (visible+hidden) on every world build. Audit via `window.__tw.ledger()` → `{pools, sum, balanced, worldDrift, stockpileByLayer}`. Worker pickup/placement now routes through the shared `spawnBlockInto`/`removeBlockFrom` helpers + `syncGroundAfterRemove/Place` (no more inlined mutation logic).

Protection field = coarse 8×8-column cell grid (`protCells`); cell mass = Σ block density, maintained incrementally via hooks in `spawnBlockInto`/`removeBlockFrom` (the only two mutation paths). `protectionAt(vx,vz)` sums nearby cells with gravity falloff `m/(1+dx²+dz²)`. Catch-up rift now opens **deterministically at the lowest-protection perimeter cell** (was random).
